## Verdict

**NO-SHIP as a stable release. The source tree is a closed-alpha candidate.**

Identity validation passes. Current cross-platform source gates are being verified.
No 0.7.0 VSIX is staged; candidate packaging is in progress.

Packaging is no longer circular, in both directions:

- Candidate creation and evidence validation are separate commands. `vscode:prepublish` runs lockfile and identity checks plus the automated test chain — Marketplace identity, URLs, provider documentation URLs — which a human can supply before any artifact exists. Screenshots of the packaged build are evidence, not identity: they moved to the evidence stage, and `media/screenshots/` is not packaged, so adding one never changes the artifact it proves. `npm run package` builds the candidate, verifies it, and prints its SHA-256. It runs no human-evidence gate, because that evidence can only be produced by testing the artifact it would gate.
- The four artifact-binding records — `RELEASE_VALIDATION_RECORD.md`, `PROVIDER_TERMS.md`, `COMPATIBILITY_MATRIX.md`, and this file — are excluded from the VSIX. Packaging a document that names the VSIX's own hash would change that hash every time it is bound. They are removed from `package.json` `files`; `verify-vsix.mjs` fails if any reappears inside the artifact, and a test fails if the packaged documentation set drifts from the repository's.
- Exactly one packaging strategy is declared. VSCE 3.9.2 exits non-zero when both a `files` property and a `.vscodeignore` are present, so there is no `.vscodeignore`; a test asserts it stays absent.
- `npm run release:bind` writes the measured hashes into those records. It voids only rows whose own result column is recorded *and* that name a different artifact hash. A recorded row that names no hash is fatal: the binder writes nothing and exits non-zero unless `--void-unbindable` is given. It plans every document before writing any, and refuses the whole operation on a malformed table or a missing binding line. The verdict document is bound but never row-voided: its tables are measurements, not artifact-bound records.
- Every record table names its artifact per column: `VSIX SHA-256` and, where the Browser Bridge is involved, `Bridge SHA-256`. Which artifacts each table must name is fixed in `scripts/lib/releaseMetadata.mjs`, not by the document: removing a column or a whole table fails the gate. Every artifact a table declares must be named in every recorded row; there is no way to excuse one.
- `npm run release:verify` is one command, not two: it fingerprints the artifact, validates identity, evidence, and binding, verifies the packaged bytes, and fingerprints again. An archive replaced or repacked between the two checks is refused rather than half-verified.

The order is therefore: build the candidate, validate it by hand, bind, verify. Human-only records remain unrecorded. Publisher `Rememo` and canonical GitHub URLs are configured; public identity no longer blocks candidate packaging. No gate was weakened or bypassed to produce an artifact.

Arm identity is checked, not trusted. The paired Fix arm is `paired-managed-fix`, which
reaches consensus on the diagnosis, splits implement and review, and is still verified by
the controller. `managed-fix` assigns one Worker, so it is a single arm; a test asserts
both facts against the presets themselves.

Arm comparability is checked before scoring. `validateTaskDesign` refuses a task whose
arms declare different required verification, a fix task with no controller verification
in any arm, and a fix task with no reference implementation. Fix correctness is no longer
self-reported: a fix run must commit the files it produced, and the harness compares them
against the task's committed reference before it will call the run correct.

A recorded run is scored only when its provenance validates: declared pipeline for that
arm, matching extension version, sha256 of the artifact under test, sha256 of the
committed fixture, provider name/adapter/model, and a committed run bundle. A record
that fails any of these is printed as rejected, exits the harness non-zero, and blocks
every claim.

No result in either artifact was produced by an agent. Both are scaffolding plus rules;
both stay empty until a human runs them.

| A packaged 0.7.0 VSIX | none exists, so its file count and uncompressed size are unmeasured |

`typescript` and `ts-morph` exist for the TypeScript/JavaScript graph context in
`src/context/tsJsContext.ts`. They are already behind a lazy `require`, reached only when
that context is built, so they cost install size rather than activation time; a test fails if
an eager import is introduced. The build emits per-file output rather than bundling, so those
dependencies ship as installed trees.

Accepted, not fixed: bundling the runtime would replace the emit-based build and change what
`verify-vsix` compares, which is not a change to make while the release gate is the thing
proving the artifact. The cost is recorded here so it is a decision rather than an oversight.

## Source-tree identity

No standalone 0.7.0 source-checksum manifest exists. `BUILD_FACTS.md` records the digest
of the Git-tracked maintained-source set. `npm run source:export -- <new-directory>` exports
the maintained distribution, and `npm run source:verify -- <directory>` checks that export.
Neither source digest is a substitute for the staged VSIX hash used by the release gate.

## What must happen before a stable claim

1. Complete current automated gates and retain the verified candidate artifacts.
2. Capture screenshots from the exact packaged build into `media/screenshots/`.
3. Keep the exact tested VSIX, then bind every human record to its hash. A rebuild needs fresh artifact acceptance. `docs/RELEASE_VALIDATION_RECORD.md`, `docs/PROVIDER_TERMS.md`, and `docs/COMPATIBILITY_MATRIX.md` each carry an `Artifacts under test:` line that the gate compares against the staged artifacts; a record produced from any other artifact is void.
4. Complete `docs/HUMAN_E2E.md` and `docs/LIVE_SMOKE_TEST.md` against that artifact on macOS, Linux, and Windows.
5. Complete the provider terms review.
6. Re-run `npm run check:release-metadata`. It passes only when every record is structurally complete and bound to the staged artifact.
7. Record both arms of every benchmark task and re-run `node scripts/benchmark.mjs`. Until then the harness prints that it supports no claim about pairing, and no pairing claim may appear in any public text.
